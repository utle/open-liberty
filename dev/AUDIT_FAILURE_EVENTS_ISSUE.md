# Audit Failure Events Not Being Generated - Investigation Summary

## Problem
Authentication failure events (SECURITY_AUTHN with outcome="failure") are NOT being generated by Open Liberty, even when:
- Wrong passwords are used (returns HTTP 401)
- Audit events are configured in server.xml
- Application requires authentication (web.xml security constraints)

## Investigation Results

### Test Performed
```bash
curl -k -u admin:wrongpassword https://localhost:9443/auditTest/
```

**Result:** HTTP 401 Unauthorized (correct behavior)
**Audit Event Generated:** NONE (incorrect - should generate SECURITY_AUTHN failure event)

### Current Audit Log Status
- **Total events in audit-output.log:** 3589 lines
- **Success events:** ALL events show `"outcome": "success"`
- **Failure events:** 0 (ZERO)

### Configuration Verified
1. ✅ server.xml has audit events configured:
   ```xml
   <events name="SECURITY_AUTHN_FAILURE" eventName="SECURITY_AUTHN" outcome="failure"/>
   ```

2. ✅ web.xml has security constraints requiring authentication

3. ✅ Server restarted after configuration changes

4. ✅ Utility recompiled with correct code (50% success, 50% failure attempts)

## Root Cause

**Liberty's audit system is NOT capturing authentication failures at the HTTP Basic Auth level.**

Possible reasons:
1. Authentication failures at the HTTP layer may not trigger SECURITY_AUTHN events
2. The audit handler may only capture successful authentications
3. Additional configuration may be required to enable failure auditing
4. This may be a known limitation or bug in Liberty's audit feature

## Workaround Options

### Option 1: Use Application-Level Authentication
Instead of relying on HTTP Basic Auth failures, create a servlet that:
1. Accepts credentials as parameters
2. Programmatically calls Liberty's authentication API
3. Explicitly logs audit events for both success and failure

### Option 2: Generate Custom Audit Events
Create a custom audit event generator that:
1. Uses Liberty's Audit API directly
2. Programmatically creates SECURITY_AUTHN events with failure outcomes
3. Bypasses the HTTP authentication layer

### Option 3: Use SECURITY_AUTHZ Events Instead
Since authorization denials ARE being logged, modify the approach:
1. Create endpoints with different role requirements
2. Use correct authentication but insufficient authorization
3. Generate SECURITY_AUTHZ denied events instead of SECURITY_AUTHN failure events

## Recommendation

**This appears to be a Liberty audit feature limitation or configuration issue, not a problem with the utility.**

To proceed, you have three options:

1. **Accept success-only events** - Use the utility as-is to generate thousands of success events
2. **Implement workaround** - Modify approach to use authorization denials or custom audit events
3. **Investigate Liberty audit** - Research Liberty documentation or source code to find how to enable failure event logging
